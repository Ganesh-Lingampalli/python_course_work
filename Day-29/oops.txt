OOPS (Object-Oriented Programming) – Short Theory Notes
What is OOP?

OOP (Object-Oriented Programming) is a programming approach that organizes programs using classes and objects. It helps in making code more organized, reusable, secure, and easier to maintain.

====================================================================================================
1. Class

A class is a blueprint or template used to create objects.

It defines the common properties (data) and behaviors (methods) that objects will have.

Example:
Student is a class. It can define properties like name and age and behaviors like studying.

====================================================================================================
2. Object

An object is an actual instance of a class.

A class can be used to create multiple objects.

Example:
If Student is a class, then Ganesh, Rahul, and Ravi can be objects of that class.

Simple:
Class = Blueprint
Object = Actual thing created from the blueprint

====================================================================================================
3. Encapsulation – Instagram Example

Encapsulation means combining data and the methods that operate on that data into a single unit and controlling access to the data.

Example: Instagram
Instagram stores information such as username, password, email, and followers. Sensitive information like the password should not be directly accessible to everyone. Access and changes are controlled through specific features.

Main purpose: To protect and control data.

====================================================================================================
4. Inheritance – LinkedIn Example

Inheritance allows one class to acquire the properties and behaviors of another class.

Example: LinkedIn
A general User can have common features such as creating a profile and sending messages. A JobSeeker or Recruiter can use these common features and also have their own additional features.

Main purpose: To reuse existing code and avoid repetition.

====================================================================================================
5. Polymorphism – YouTube Example

Polymorphism means "many forms." The same action or method can behave differently depending on the object.

Example: YouTube
The action play() can be used for different content. It may play a video, a song, or a short. The action is the same, but its behavior depends on the type of content.

Main purpose: To make programs flexible and easier to extend.

====================================================================================================
6. Abstraction – PhonePe Example

Abstraction means hiding complex internal details and showing only the necessary features to the user.

Example: PhonePe
To send money, the user enters the amount, selects a person, enters the UPI PIN, and clicks Pay. The user does not need to know how the bank verifies the transaction or how the money is transferred internally.

Main purpose: To reduce complexity and make systems easier to use.
====================================================================================================
6. What is Polymorphism? — YouTube Example
Polymorphism means "many forms." It allows the same method or interface to behave differently depending on the object using it.

YouTube example:
YouTube has different types of content such as:

Normal videos
YouTube Shorts
Live streams

All of these can have a common operation such as play. However, the way each type of content is played can be different.
A normal video may play like a regular video, a Short may use vertical short-form playback, and a live stream may provide real-time streaming.
So, the same operation—play—can have different behaviors.

============================================================================================================================================================================================

7. What is Abstraction?
Abstraction is the process of hiding complex implementation details and showing only the essential functionality to the user.

ATM example:
When we use an ATM, we simply select options such as Withdraw Money or Check Balance.
We don't need to know the internal processes such as:

Authentication
Database communication
Balance verification
Transaction processing
Updating the bank account

These complex operations are hidden from the user.
